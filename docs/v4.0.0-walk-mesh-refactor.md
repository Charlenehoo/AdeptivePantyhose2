# v4.0.0 架构重构提案：从事件驱动到渲染层同步

**版本**：v4.0.0 设计草案
**日期**：2026-11-01
**状态**：设计阶段，待评审与验证

---

## 1. 背景与动机

v3.0.5 及之前的版本采用 **"增量事件驱动（Event-Driven Incremental）"** 架构：

1. 依赖 `TESEquipEvent` 和 `GetWornArmor` 感知装备变化。
2. 使用 `TriggeredBy` 元数据在数据层（Inventory）合成状态。
3. 在回调栈（如 `TESEquipEvent` / `OnAttach`）中直接执行 D3D / Morph 操作。

这套架构在处理边缘场景（Modex 换装、脚本强制换装、工作线程回调）时，暴露出三个不可调和的矛盾，导致代码中充满补丁与防御性逻辑（如 §5.2 状态合成、§7.7 旧值修正、§10.1 线程亲和性修复）：

1. **数据层与渲染层的时序错位**：`TESEquipEvent` 期间 `GetWornArmor` 返回旧值；Modex 的 `AddWornItem` 不触发事件。导致必须写复杂的合成逻辑，且无法覆盖非标准事件。
2. **事件栈内的上下文脆弱性**：`OnAttach` 跨线程（工作线程）且处于 `AttachBipedObject` 的 D3D 窗口期，直接操作容易引发竞态（与 IED 冲突）或固化错误的 `SHAPEDATA`。
3. **Mod 兼容性的灾难**：基于 `FormID` 或 `Keyword` 的匹配，在遇到"轻甲修复补丁"、"幻化替换"、"SMP 物理版"时全部失效，因为 FormID 变了，而原作者往往不加规范的 Keyword。

**核心洞察：我们的最终目的是修改 Mesh（渲染层），就不应该依赖 TESObjectARMO（数据层）来指导操作。我们应该直接"看"当前屏幕上到底渲染了什么。**

### 1.1 设计哲学：兼容性的本质

在重构架构之前，必须承认一个残酷的物理事实：**视觉兼容不是一个可计算问题，它来自艺术家的私有实现。**

正如社区用户 `rudeboybox` 所总结的：

> "我意识到（把不同作者的衣服混搭）是不可能的……除非它们有滑条，而且只有专门为了匹配而建的裤袜和鞋（比如来自同一个作者）才能生效。"

Caenarvon 之所以能实现完美的贴合，是因为她在 BodySlide 里使用了同一套底层脚模。换一个作者，只要底模拓扑或 UV 不同，Morph 的视觉效果就会崩坏。

因此，v4.0.0 不试图实现"全自动的通用视觉适配"。相反，我们通过 **Walk Mesh** 拥抱渲染现实，通过 **NIF 路径** 锚定具体的资产特征，用人类可读的规则去补全这些"私有实现"的映射关系。

## 2. 核心架构变更：四大支柱

v4.0.0 引入 **"状态同步（State-Synchronization）"** 范式，包含四大支柱。

### 2.1 单一触发源（SSOT）：抛弃 TESEquipEvent

彻底移除 `TESEquipEvent` 监听。`IAddonAttachmentInterface::OnAttach`（Mesh 挂载）是引擎唯一无法被绕过的信号。无论上层是 Modex、控制台还是脚本，只要 Mesh 出现了，就必然触发重算。

### 2.2 全局脏位（Global Dirty Bit）：回调只记录，1 bit 翻转

在 `OnAttach`（无论主线程还是工作线程）中，不读取任何游戏状态，不调用 SKEE 接口，不碰 D3D。只做一件事：

```cpp
g_dirty.store(true, std::memory_order_relaxed);
```

多个工作线程并发写 `true` 是绝对线程安全的，零锁、零分配、零开销，彻底解决 IED 的线程亲和性冲突。

> 早期草案曾考虑用 `std::unordered_set<RE::FormID>` 记录具体脏 Actor（Dirty Set）。改为全局 1 bit 后，回调路径不再分配内存、不再加锁，代价是全量重算的范围扩大到所有已加载 Actor——这一代价由 §5 的 Tier 优先队列与帧级限流吸收。

### 2.3 异步全量同步（Async Full Evaluation）

利用主线程的 `SKSE::GetTaskInterface` 或 Tick 监听器。每帧检查一次脏位：

```cpp
if (g_dirty.exchange(false, std::memory_order_acquire)) {
    ProcessAllActors();
}
```

`exchange` 保证了原子性。如果主线程处理期间又有新的 `OnAttach`，脏位会再次被置为 `true`，顺延到下一帧处理。

### 2.4 渲染层驱动（Walk Mesh）：抛弃 TriggeredBy

全量求值时，**彻底废弃 `TriggeredBy`**，抛弃 `GetWornArmor`。
直接遍历 `Actor::GetBiped()->objects` 和 `bufferedObjects`：

```cpp
for (auto& data : weightModel->objects) {
    if (data.partClone && data.partClone->parent != nullptr) {
        // 此处的 data.item 和 data.partClone 是 100% 当前正在渲染的真实状态
    }
}
```

只要 `data.partClone` 存在且 `parent != nullptr`，它就是当前真实渲染的 Mesh。拿这个真实 Mesh 对应的 `ARMOR` 和 `NIF 路径` 去跑谓词规则。命中则应用，所见即所得。

## 3. 谓词演进与配置重构

因为改为 Walk Mesh，当前的 Mesh 自身就包含了它属于哪个槽位、对应哪件装备的所有上下文，`TriggeredBy` 字段被彻底删除。

### 3.1 新增 `ByNifPath` 谓词

针对"轻甲修复版"、"幻化（FormID 变动）"问题，引入基于 NIF 路径的匹配。

```json
{
  "Predicates": {
    "CaenarvonHeels": {
      "ByNifPath": ["*caenarvon*", "*heel*"]
    }
  }
}
```

### 3.2 配置示例

```json
{
  "Morphs": {
    "NoHeel": {
      "Rules": [
        { "Value": 0.0, "When": "CaenarvonHeels" },
        { "Value": 1.0, "When": "Default" }
      ]
    }
  }
}
```

_注：当 Walk 到裤袜 Mesh 时，用裤袜的 ARMOR 跑 `CaenarvonHeels`（不命中跳过）；当 Walk 到鞋的 Mesh 时，命中，应用 `NoHeel=0`。_

## 4. 数据流对比

### 旧架构（v3.0.5）

```
TESEquipEvent → 状态合成(GetWornArmor) → 谓词求值 → SetAbsolute → ApplyVertexDiff
(Modex失效)     (旧值Bugs)                (TriggeredBy)  (主线程/工作线程混乱)
```

### 新架构（v4.0.0）

```
OnAttach (任意线程) ──► MarkDirty(FormID)
                             │
                             ▼ (下一帧主线程 Task)
                    Walk Mesh (bipedData->partClone)
                             │
                             ├─► 提取 ARMOR / ARMA / NifPath
                             ├─► 遍历 Rules，求值 (谓词)
                             └─► SetAbsolute + ApplyVertexDiff (当前Mesh)
```

## 5. 调度与性能保障（帧级预算）

在主线程 Task 中进行全量计算时，必须采用极其严苛的预算控制，防止"网格重建风暴"。

### 5.1 值比对（Value Diffing）：屏蔽无效 D3D 操作

遍历求值后，先比对缓存中的当前 morph 值（或调用 `GetMorph`）。如果计算出的值与当前值一致，直接 `continue`。**绝对不对未发生变化的 Mesh 调用 `ApplyVertexDiff`。**

### 5.2 优先队列：玩家绝对优先

- **Tier 0（玩家）**：`PlayerCharacter::GetSingleton()` 的更新绝对优先，无视预算，当帧立即执行完毕。
- **Tier 1（高优先）**：`ProcessLists::highActorHandles` 和 `middleHighActorHandles`。
- **Tier 2（低优先）**：`lowActorHandles`（通常已被 LOD 门禁过滤）。

### 5.3 LOD 门禁（Is3DLoaded）

遍历 Actor 时，首先检查 `actor->Is3DLoaded()`。如果为 `false`（比如在另一个房间、或距离极远被引擎卸载了渲染），直接 `continue`。连 Walk Mesh 都不做，因为他穿了什么玩家根本看不见。

### 5.4 帧级限流（Throttling）

给非玩家 Actor 设定每帧的处理预算（例如 `budget = 5`）。遍历 `ProcessLists` 时，如果预算耗尽，直接 `g_dirty.store(true)` 留给下一帧，绝不阻塞主线程的渲染。玩家肉眼根本感觉不到远处的 NPC 晚了一两帧才变形。

### 5.5 风险与边界

1. **无 Mesh 的隐形装备**：如果某件装备不产生 Mesh（如 buff 戒指），它不会触发 `OnAttach`，因此不会触发重算。考虑到本插件仅修改视觉形态，此限制完全可接受。
2. **全局状态谓词**：有些规则可能依赖"角色全身状态"（如：穿了高跟鞋，且穿了裤袜，才触发）。在 Walk Mesh 时，谓词内部依然可以通过 `a_actor->GetWornArmor()` 读取全局状态进行判断。

## 6. 落地计划（分阶段演进）

不要一把梭哈，采用"剥洋葱"式的四步走：

### 阶段一：基建期（消灭线程竞态）

- 引入全局脏位 `g_dirty`。
- `AttachListener` 改为只置位，求值逻辑移至主线程 Task。
- **目标**：发 v3.1.0，彻底解决 GOODNEWSGN 的 IED 工作线程冲突隐患。

### 阶段二：双轨期（影子模式验证）

- 引入 `ByNifPath` 谓词与 Walk Mesh 逻辑。
- 新逻辑只写日志（`[WalkMesh] Would apply...`），不实际写入。
- 对比旧逻辑与新逻辑的日志，验证 NIF 路径命中的准确性。

### 阶段三：纯血期（架构瘦身）

- 彻底移除 `TESEquipEvent`、`TriggeredBy` 和旧的状态合成逻辑。
- 引入值比对与 `ProcessLists` 限流。
- **目标**：发布 v4.0.0，代码量减少三分之一。

### 阶段四：远期展望（Out of Scope）

**脱离 Morph 体系的几何形变（v5.0.0+）**
基于 UV 流形与单射位移场的自适应网格形变算法，旨在彻底摆脱对 BodySlide / Morph Target 体系的依赖。该方案属于图形学算法范畴，已剥离至独立文档 [v5.0.0-uv-displacement-field.md](v5.0.0-uv-displacement-field.md)，不在本次 v4.0.0 重构讨论范围内。

### 工程任务清单

1. **基础重构**：抽离 `EvaluateFull(actor)`，引入全局脏位与主线程 Task 限流机制。
2. **逻辑替换**：移除 `EventProcessor`（`TESEquipEvent`），在 `OnAttach` 中做 `MarkDirty`。
3. **Walk Mesh 接入**：废弃 `TriggeredBy`，将求值入口从按 Morph 遍历改为按 Mesh 遍历。
4. **谓词扩展**：实现 `ByNifPath` 叶子工厂，编写配套的 PAS 脚本。
5. **测试验证**：重点验证 IED 冲突是否消失（线程问题解决）、Modex 兼容性、以及轻甲修复版的 NIF 命中率。
