# v4.0.0 架构重构提案：从事件驱动到渲染层同步

**版本**：v4.0.0 设计草案
**日期**：2026-11-01
**状态**：设计阶段，待评审与验证

---

## 1. 背景与动机

v3.0.5 及之前的版本采用 **“增量事件驱动（Event-Driven Incremental）”** 架构：

1. 依赖 `TESEquipEvent` 和 `GetWornArmor` 感知装备变化。
2. 使用 `TriggeredBy` 元数据在数据层（Inventory）合成状态。
3. 在回调栈（如 `TESEquipEvent` / `OnAttach`）中直接执行 D3D / Morph 操作。

这套架构在处理边缘场景时，暴露出三个不可调和的矛盾，导致代码中充满了补丁（如 §5.2 状态合成、§7.7 旧值修正、§10.1 线程亲和性修复）：

1. **数据层与渲染层的时序错位**：`TESEquipEvent` 期间 `GetWornArmor` 返回旧值；Modex 的 `AddWornItem` 不触发事件。导致我们必须写复杂的合成逻辑，且无法覆盖非标准事件。
2. **事件栈内的上下文脆弱性**：`OnAttach` 跨线程（工作线程）且处于 `AttachBipedObject` 的 D3D 窗口期，直接操作容易引发竞态（与 IED 冲突）或固化错误的 `SHAPEDATA`。
3. **Mod 兼容性的灾难**：基于 `FormID` 或 `Keyword` 的匹配，在遇到“轻甲修复补丁”、“幻化替换”、“SMP 物理版”时全部失效，因为 FormID 变了，而原作者往往不加规范的 Keyword。

**核心洞察：我们的最终目的是修改 Mesh（渲染层），就不应该依赖 TESObjectARMO（数据层）来指导操作。我们应该直接“看”当前屏幕上到底渲染了什么。**

## 2. 核心架构变更

v4.0.0 引入 **“状态同步（State-Synchronization）”** 范式，包含四大支柱：

### 2.1 单一触发源（SSOT）

**抛弃 `TESEquipEvent`，拥抱 `IAddonAttachmentInterface::OnAttach`。**
`OnAttach` 是引擎挂载 Mesh 的唯一必经之路，无论上层是 Modex、脚本还是控制台，只要 Mesh 出现了，`OnAttach` 必然触发。

### 2.2 回调只记录（Dirty Marking）

在 `OnAttach`（无论主线程还是工作线程）中，**不读取任何游戏状态，不调用 SKEE 接口，不碰 D3D**。
只做一件事：将 `a_refr->GetFormID()` 塞入一个线程安全的 `std::unordered_set<RE::FormID>`（Dirty Set）。

### 2.3 异步全量求值（Async Full Evaluation）

利用 `SKSE::GetTaskInterface()`，在主线程的下一个 Tick 中：

1. 取出 Dirty Set 中的 Actor，清空 Set。
2. 对每个 Actor 执行全量求值。

### 2.4 渲染层驱动（Walk Mesh）

全量求值时，**抛弃 `GetWornArmor` 和 `TriggeredBy`**。
直接遍历 `Actor::GetBiped()->objects` 和 `bufferedObjects`：

```cpp
for (auto& data : weightModel->objects) {
    if (data.partClone && data.partClone->parent != nullptr) {
        // 此处的 data.item 和 data.partClone 是 100% 当前正在渲染的真实状态
    }
}
```

## 3. 谓词演进与配置重构

由于我们改为 Walk Mesh，`TriggeredBy` 字段**被彻底删除**。因为当前的 Mesh 自身就包含了它属于哪个槽位、对应哪件装备的所有上下文。

### 3.1 新增 `ByNifPath` 谓词

针对“轻甲修复版”、“幻化”等 FormID 变动问题，引入基于 NIF 路径的匹配。

```json
{
  "Predicates": {
    "CaenarvonHeels": {
      "ByNifPath": ["*caenarvon*", "*heel*"]
    }
  }
}
```

### 3.2 配置示例

```json
{
  "Morphs": {
    "NoHeel": {
      "Rules": [
        { "Value": 0.0, "When": "CaenarvonHeels" },
        { "Value": 1.0, "When": "Default" }
      ]
    }
  }
}
```

_注：当 Walk 到裤袜 Mesh 时，用裤袜的 ARMOR 跑一遍 `CaenarvonHeels`（没命中，跳过）；当 Walk 到鞋的 Mesh 时，命中，应用 `NoHeel=0`。_

## 4. 数据流对比

### 旧架构（v3.0.5）

```
TESEquipEvent → 状态合成(GetWornArmor) → 谓词求值 → SetAbsolute → ApplyVertexDiff
(Modex失效)     (旧值Bugs)                (TriggeredBy)  (主线程/工作线程混乱)
```

### 新架构（v4.0.0）

```
OnAttach (任意线程) ──► MarkDirty(FormID)
                             │
                             ▼ (下一帧主线程 Task)
                    Walk Mesh (bipedData->partClone)
                             │
                             ├─► 提取 ARMOR / ARMA / NifPath
                             ├─► 遍历 Rules，求值 (谓词)
                             └─► SetAbsolute + ApplyVertexDiff (当前Mesh)
```

## 5. Trade-off 与风险评估

1. **性能（限流机制）**：NPC 批量加载时，可能会有几十个 Actor 同时 Dirty。如果在同一帧的 Task 里对几十个 Actor 执行 `Walk Mesh + UpdateModelWeight`，会导致主线程卡顿。
   - **解决方案**：在主线程 Task 中引入限流（Throttling），例如每帧最多处理 5 个 Actor，剩余顺延到下一帧。
2. **无 Mesh 的隐形装备**：如果某件装备不产生 Mesh（如 buff 戒指），它不会触发 `OnAttach`，因此不会触发重算。考虑到本插件仅修改视觉形态，此限制完全可接受。
3. **全局状态谓词**：有些规则可能依赖“角色全身状态”（如：穿了高跟鞋，且穿了裤袜，才触发）。在 Walk Mesh 时，谓词内部依然可以通过 `a_actor->GetWornArmor()` 读取全局状态进行判断。

## 6. 远期展望：基于 UV 流形与单射位移场的自适应网格形变（v5.0.0+）

本插件的终极目标是完全摆脱对 BodySlide / Morph Target 体系的依赖，实现“物理级”的衣物自适应。

### 6.1 核心不变量（The Invariants）

1. **材质兼容不变量**：艺术家在制作任何非标准脚模（如踮脚尖的高跟脚）时，为了复用通用的皮肤/丝袜材质，必须兼容原始平脚的 UV 展开。因此，所有脚模在 UV 空间（及其商空间）天然具有映射关系。
2. **拓扑存在不变量**：任何鞋型要么内嵌了脚模（如靴子），要么未内嵌（如凉鞋）。只要露出脚，就必然有脚模数据。

### 6.2 算法管线设计

1. **无脚模场景（如凉鞋）**：直接对长筒袜模型应用 Mask 裁剪，不渲染其“脚”部分的网格，从而避免强行拉伸导致的穿模。
2. **有脚模场景（如高跟靴）**：
   - **UV 拉回**：将平脚模型与高跟脚模的 3D 流形拉回 UV 坐标的商空间（处理 UV 岛的多对一映射，保证纤维连续性）。
   - **计算位移场**：在 UV 空间计算从平脚到高跟的单射位移场（Injective Displacement Field）。
   - **邻域形变传递**：由于丝袜必然在脚模的拓扑邻域内，将该位移场直接施加于丝袜网格，实现像素级贴合。

### 6.3 性能与工程分层

- **离线烘焙（Blender Python）**：对于复杂的非线性形变（如 ARAP 算法），通过离线脚本预计算位移场，导出为材质偏移贴图或顶点缓存。
- **运行时计算（C++）**：利用拉普拉斯形变（Laplacian Deformation）求解稀疏线性方程组，在毫秒级内对局部网格（脚部区域）进行实时形变。

> _注：该远景规划涉及微分几何与图形学算法，脱离当前基于 Biped/Morph 的游戏引擎常规机制，作为 v4.0.0 架构迭代之后的独立研究课题。_

## 7. 落地计划

1. **基础重构**：抽离 `EvaluateFull(actor)`，引入 Dirty Set 与主线程 Task 限流机制。
2. **逻辑替换**：移除 `EventProcessor`（`TESEquipEvent`），在 `OnAttach` 中做 `MarkDirty`。
3. **Walk Mesh 接入**：废弃 `TriggeredBy`，将求值入口从按 Morph 遍历改为按 Mesh 遍历。
4. **谓词扩展**：实现 `ByNifPath` 叶子工厂，编写配套的 PAS 脚本。
5. **测试验证**：重点验证 IED 冲突是否消失（线程问题解决）、Modex 兼容性、以及轻甲修复版的 NIF 命中率。
